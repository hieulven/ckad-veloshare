## Microservices design & principal patterns

### Core design (present — strong)

| Pattern / principle | How it appears |
|---------------------|----------------|
| Bounded context / single responsibility | movie / booking / payment / notification / api-gateway |
| Database-per-service | Separate Postgres StatefulSets: movie, booking, payment, notification |
| Independent deployability | Per-service Dockerfile + tagged `1.0.0` images + Deployments |
| API Gateway | `api-gateway` (JWT, rate limit, NodePort 30080) |
| Sync HTTP east-west | Gateway→APIs; booking→movie; payment→booking via K8s DNS |
| Async event-driven | Payment publishes to RabbitMQ topic exchange; notification consumes |
| Health contracts | `/healthz`, `/ready` on services |
| Externalized config | Per-service ConfigMap + Secret (`envFrom`); secrets generated by scripts |

### Communication & integration

| Pattern | Status |
|---------|--------|
| Sync request/response (HTTP) | **Real** |
| Async messaging (RabbitMQ topic exchange `booking.events`) | **Real** — publish + consume code, not mock strings |
| Idempotent consumer | **Real** — `INSERT … ON CONFLICT DO NOTHING` + ack-after-process |
| Polyglot persistence | **Real** — Postgres + Redis (holds TTL) + RabbitMQ + MailHog |
| Shared database anti-pattern | **Avoided** |

### Kubernetes / cloud-native patterns

| Pattern | Where |
|---------|--------|
| Init container | DB migrate / wait-backends |
| Sidecar log shipper | `log-shipper:1.0.0` + `emptyDir` logs |
| Ambassador / proxy sidecar | `nginx-ambassador` on 9090; Service `targetPort: 9090` |
| StatefulSet + PVC | Per-service Postgres; RabbitMQ PVC |
| HPA | `booking-service-hpa` |
| Blue/green | `labs/lab-2.2` (selector flip) — not in main app Deployments |
